## 1. Review
오늘은 크롤러를 AWS Lambda 환경에서 실행하는 것까지 성공했다.
데이터 프로덕트 검증을 위해 최근 사례 조사 중 ‘Tesla Autopilot’ 사태가 8월 2일에 발생한 것을 확인했는데, 실제로 X와 Threads 데이터를 수집해 분석해 보니 8월 2일 18시 무렵 언급량이 급격히 증가하는 현상을 시각적으로 확인할 수 있었다.
다만 원시 데이터에는 노이즈가 많아 변화 시점을 정확히 보기 어려웠는데, 이동평균(Moving Average) 기법을 적용한 시각화를 통해 확실히 언급량이 급증한 시간대 구간을 파악할 수 있었다.
이번 작업을 통해 가장 크게 느낀 점은 SNS 크롤링의 난이도였다.
수차례 429 rate limit 에러와 IP 차단을 경험했고, 이를 피하기 위해 쿠키를 여러 번 재설정하고 계정을 새로 만드는 등의 우회 방법이 필요했다.
또한 단순 HTML이 아닌 JavaScript 기반 동적 페이지 구조였기 때문에, 네트워크 탭의 GraphQL 응답을 추적해야만 원하는 데이터를 얻을 수 있었다.
이 과정에서 시행착오가 많았지만, 실제로 데이터를 수집·분석하며 사건과 여론의 시계열적 변화를 포착할 수 있었던 점이 오늘의 가장 큰 성과였다.

## 2. Keep (잘한 점)
아침에 일찍 도착해서 작업한 점. 아침에 혼자 조용히 작업하니까 잘됐다.

## 3. Problem (문제점)
Timeboxing을 제대로 못한 점. 에러가 하나 발생했을 때 계속 붙잡고 있었다.
그리고 남들보다 작업속도가 뒤처지는것 같다.

## 4. Try (구체적인 개선 방안)
집에 가서 잔업하기. 이때도 오늘 안에 끝낼 작업을 하나 명확히 정하고 Timeboxing을 적용하여 빠르게 끝낸다.
