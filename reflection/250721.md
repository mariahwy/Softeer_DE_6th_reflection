- 오늘의 배운 점은 다음과 같다.
  - Hadoop
    - 제작 배경이나, 어떠한 선택을 통해 데이터 프로덕트가 만들어진 것인지 고민하는 과정이 중요하다는 것을 깨달았다.
    - Store, Process 두 가지의 문제를 해결한다.
    - Modules
        - Hadoop Common - Common은 뭔지 모르겠어서 찾아봐야겠다.
        - HDFS : Store (Storage Layer)
        - Hadoop Yarn : 과정 관리 (Resource Management Layer)
        - Hadoop MapReduce : Process (Application Layer)
  - Architecture
    - Master Node (Name Node), Slave Node (Data Node)
  - HDFS (Hadoop Distributed File System)
    - 기본 가정과 목표
        - 하드웨어는 항상 고장날 것이다. → block replication
        - 데이터를 스트리밍으로 접근할 수 있어야 한다.
        - 큰 데이터셋
        - Simple Coherence Model  (극단적으로 cost 줄임)
            - WORM (한 번 쓰면 수정 x, 읽기 많음)
            - 접근하려는 데이터가 업데이트 전인지 후인지 판단할 필요 x (lock cost 0)
            - 추후 업데이트 가능하도록 수정됨
        - Heterogeneous Hardware and Software : 하드웨어가 단종되어도 대체 가능
    - Data Locality
        - Data Local
        - Rack Local : 같은 Rack의 데이터를 사용하는 게 싸다 (Rack끼리 중복 저장되어있음)
- Hadoop Yarn (Yet Another Resource Manager)
    - resource management vs job scheduling/monitoring 분리 (seperate daemon)
    - RM (resource manager)
    - AM (application manager)
  - Client → RM → AM → Container
    - 만약 장애 발생하면? RM 병목
    - 각 AM이 관리하고, RM은 병목 없도록 RM과 AM을 분리
- replica가 증가할수록 저장 cost 증가 ↔ 탐색 cost 감소 (locality 증가)
- Hadoop MapReduce
    - Hadoop MapReduce는 **저렴한 서버 여러 대를 묶어 큰 데이터를 병렬로 처리할 수 있게 해 주는, 신뢰성 있는 소프트웨어 프레임워크**
    - 병렬 처리를 사용하여 대규모 데이터 처리 속도를 높이는 프로그래밍 모델
    - Map Phase
        - 첫 번째는 '매핑 작업'으로, 한 세트의 데이터를 가져와 **키/값 쌍으로 포맷**된 다른 데이터 세트로 변환.
        - RecordReader
        - Map
        - Combiner
        - Partitioner   
        → **로컬디스크**에 저장 (Map의 결과)
    - Reduce Phase
        - 두 번째는 '축소 작업'으로, 매핑 작업의 아웃풋을 가져와 동일한 키를 가진 모든 값을 집계하고 데이터를 처리하여 최종 키/값 쌍 세트를 생성.
        - Sort and Shuffle: 네트워크 통신하면 느려짐 → 셔플을 하면 네트워크 해야됨 → 셔플을 안 하게 하는 코드가 좋은 코드 → 돌려봤더니 셔플 되면 코드 바꿔야됨
        - Reduce
        - OutputFormat
