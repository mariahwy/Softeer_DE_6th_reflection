## 1. Review
- 오늘의 배운 점은 다음과 같이 정리할 수 있을 것 같다.
- 1. Docker 위에서의 Hadoop 운용 시 문제점과 해결책
  핵심 문제: Hadoop의 HDFS는 persistent storage를 전제로 동작하지만, Docker 컨테이너는 휘발성이 기본 특성이다. 이로 인해 두 시스템 간의 충돌이 발생.
  해결 방식: 마운트 전략을 통해 Docker 외부의 호스트 디렉토리를 HDFS 관련 디렉토리(/hadoop/dfs/name, yarn.nodemanager.local-dirs, log-dirs 등)에 연결함으로써 데이터 지속성 보장.
    실제로 YARN이 추가되면서 애플리케이션 실행에 필요한 임시 파일과 로그 파일을 별도 디렉토리에 저장하게 되며, 이 디렉토리들 또한 마운트 필요.
  느낀 점: 단순히 컨테이너를 띄우는 것만 고민해왔는데, 훨씬 고차원의 고민이 필요하며, 특히 데이터 영속성 측면에서 설계가 선행되어야 함.

- 2. Docker 이미지 관리
  의심스러운 이미지에서 출발하기보다, 신뢰 가능한 베이스 이미지를 기준으로 설정하는 것이 좋음.
  베이스 이미지에 공통 라이브러리 및 환경 설정을 한 후, 이를 기반으로 여러 목적별 서브 이미지를 구축하는 방식은 실제 현업에서도 사용되는 패턴.
  느낀 점: 버전 관리와 재현성 측면에서 이미지 계층화는 필수이며, 이를 통해 추후 유지보수도 수월해진다. 앞으로도 이렇게 해야겠다. 단, 신뢰 가능한 이미지를 위해 깃허브에 Dockerfile 버전 관리는 필수.

- 3. 우분투 환경에서의 사용자 및 권한 설정
  사용자 개념: Hadoop 자체는 사용자 개념이 없지만, 호스트 OS의 사용자 및 그룹을 통해 간접적으로 접근 권한을 제어.
  예를 들어, hdfs, yarn 사용자 계정을 별도 생성하여 해당 데몬 실행 → 실행 사용자 권한 기반으로 파일 시스템 제어.
  권한 체계: UNIX 기반의 rwx(읽기/쓰기/실행) 권한과 사용자-그룹-기타의 계층 구조 이해가 부족했는데, 필수적으로 이해해야한다.
  느낀 점: 컨테이너든 VM이든, 결국 모든 권한의 뿌리는 호스트 OS의 사용자 체계에 기반하며 이를 정확히 설정하는 것이 시스템 안정성에 직결된다.

## 2. Keep (잘한 점)
교안의 내용을 꼼꼼히 읽고, 모든 내용을 나만의 방식으로 노션에 정리해두었다. 내가 이해한 내용을 바탕으로, 나만의 언어로 정리해둔 자료이기에, 
미션을 수행하며 헷갈리는 부분이 생기면 내 기록물을 보고 해결할 수 있었다. 교안을 다시 일일이 뒤지는 것보다, 개인적으로 정리한 자료를 다시 보는
것이 훨씬 이해가 잘 됐다.

## 3. Problem (문제점)
기존에는 교안이 영어로 되어 있어서 이해하기 힘들 것 같아 한 번 대충 보고, 유튜브나 블로그 등을 보며 공부했었다.
그러다보니 개념이 파편적으로 흩어져 있다는 느낌이 들었다. 예를 들어 A블로그와 B블로그에서 자신이 이해한 방법을 작성해둔 방식이 달라서,
개념에 혼동이 오고 이해가 힘들었다. 그러다보니 W3의 미션을 수행하는 데 어려움이 있었고, Application Manager, Application Master의
차이도 이해하지 못한 상태에서 미션을 어찌저찌 마무리하게 되었다. 이렇게 미션을 수행하니, 머리에 남은 게 없다고 느껴졌고, 말로 개념을
설명하라고 요구 받았을 때, 원활하게 전달할 수 없을 것 같다는 생각이 들었다. 

## 4. Try (구체적인 개선 방안)
오늘 Spark를 배우면서 먼저 모든 교안의 내용을 이해하려고 노력했다. 그 이후 공식 문서와 블로그, 챗GPT를 이용하여 교안을 읽으며
느꼈던 의문증이나 궁금증을 해결하는 방식으로 공부해보았다. 아직 Spark를 완전히 이해하진 못했지만, 그래서 이 방식을 다음 주에도 시도해볼 예정이다.
즉, 교안을 먼저 일일이 공부한 후 의문점만을 블로그나 챗지피티와 같은 도구를 활용하여 해결할 예정이다.
또, 그동안 '사용자' 라는 개념에 관심을 가진 적이 없었는데, 확실히 보안이나 크리티컬한 이슈를 방지하기 위해서 모든 Unix 시스템에 사용자별 관리가 필수적이다. 앞으로 어떤
컨테이너를 작동시키더라도 꼭 사용자를 추가와 권한 관리를 먼저 고려할 것이다.
