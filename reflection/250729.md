## 1. Review
오늘은 AWS 강의를 들었다. AWS 권한 설정과 VPC에 대해 배웠는데, 학교 네트워크 강의에서 배웠던 CIDR과 서브넷 개념이 여기에 적용되는 거였구나라는 생각이 들면서
개념이 통합되는 느낌이었다. 교내 수업에서 배웠을 때는 단순히 기말 점수를 잘 받기 위해서 서브넷 그룹에 할당된 ip 개수 계산을 열심히 했었는데,
실제 상황에서 접하니 이제야 그 개념이 이해가 되었다.
그리고 W4M2를 시작했는데, 정말 다양한 고민을 하고 있다. 어떤 데이터를 수집할지 (yellow taxi? green taxi?,,,)부터, 몇개년 데이터를 수집할지, 그리고
데이터 수집은 따로 fetcher 컨테이너를 만들어서 할지, 수집한 데이터를 hdfs에 저장해야할지 등... 정말 많은 선택의 기로가 존재한다.
다노님께서 항상 강조하시는, 이런 고민이 생길 때 의사결정을 잘하려면 역시 Use Case를 먼저 설정해야 한다는 것을 드디어 실감했다.
그래서 '우버 택시에 대해 코로나 전후 이용자 수를 비교하고 팬데믹 리스크 대응 전략을 세우려는 우버의 리스크관리팀'을 주제로, 'High Volume For-Hire Vehicle Trip Records (PARQUET)'
의 22년도~25년도 데이터를 수집해보고자 한다.

## 2. Keep (잘한 점)
위의 리뷰 내용처럼, 오늘 미션2를 하면서 다양한 고민을 마주했다. 그래서 바로 코드를 짜기보다, 먼저 노트에 손으로 구조와 의문점을 작성해보았다. 
- fetcher container (python, selenium) -> 어떻게 효율적으로 수집할 것인가?
- spark container (master, worker) -> worker는 몇 개로 설정할 것인가? 결과를 hdfs에 저장할 것인가?
- jupyter
이런 식으로 대강 구조를 고민해보았다. 아직 더 생각할 부분이 많이 남아서, 내일도 바로 코드를 짜지 않고 이렇게 고민하고, Pseudo code를 작성해본 후, 실제로 컨테이너를
만들어 작은 부분부터 코드를 작성해나갈 것이다.
