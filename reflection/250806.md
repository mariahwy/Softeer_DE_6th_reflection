## 1. Review
오늘은 AWS 수업 때문에 미션과 팀 회의를 많이 하지는 못했다. 내일 더 열심히 해야겠다.
- AWS 수업에서 배운점
  AWS의 서버리스 서비스는 서버 관리 없이 애플리케이션을 운영할 수 있는 구조로, Lambda·API Gateway·S3·DynamoDB 등이 대표적이다.
  Lambda는 이벤트 기반으로 실행되어 사용한 만큼만 비용을 내며, Stateless 특성 때문에 상태 저장은 외부 스토리지나 DB를 사용해야 한다.
  API Gateway는 HTTP 요청을 Lambda 등과 연결해 손쉽게 API 서버처럼 동작하게 한다.
  DynamoDB는 무제한 확장이 가능한 NoSQL DB로, 파티션 키·인덱스 설계가 성능과 비용 효율에 큰 영향을 미친다.
  결론적으로 서버리스 환경에서는 메모리·RCU·WCU와 같은 성능 설정이 곧 비용과 직결되므로, 테스트를 통해 최적값을 찾는 것이 비용을 아끼는 데 중요하다.

## 2. Keep (잘한 점)
아이디어 평가표 (고통, 돈, 진짜 문제인가?) 기준으로 평가한 뒤, 통과한 아이디어를 문제정의 구체성 평가표
(아이디어 제목	프로덕트가 필요한 문제?	사용자 반응 데이터 유무	그외 데이터 존재 유무	확장성	해결 가능성?)로 마지막 평가를 해서 아이디어를 평가하려고 한 점.

## 3. Problem (문제점)
자꾸 아이디어 자체의 장단점을 평가하게 되고, 팀원 아이디어와의 차이를 평가하는 연습이 덜 되어있는 것 같다. 목적을 다시 떠올리고 그 목적에 맞는 사고를 하도록 노력해야겠다.
그리고 아이디어를 평가하는 단계를 적절히 나눠야 할 것 같다. 

## 4. Try (구체적인 개선 방안)
다른 팀원의 아이디어를 내 아이디어와 비교해보며 평가표를 채워야겠다.
